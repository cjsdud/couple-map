# 기획: 다지역 데이트 기록과 사진 귀속 (사용자 피드백 6번, 2026-07-20)

## 현재 상태 진단

**"한 기록이 여러 지역이면?"은 이미 해결돼 있다.** 1기록 = 스팟 1~5 구조에서 각 스팟이 자기 `sigungu_code`를 갖고, 정복 판정은 스팟 단위다. 서울→수원으로 이어진 데이트를 한 기록으로 넣으면 마포구와 수원시가 **둘 다** 색칠되고, 지도에는 두 지역을 잇는 점선 코스가 그려진다. 기획 변경 불필요.

**실제 공백은 "사진이 어느 지역(스팟) 것인지"다.** 사진은 기록 단위(`record_photos.record_id`)로만 붙어서:
- 기록 상세에서 스팟별로 사진을 묶어 보여줄 수 없다 (서울 사진과 수원 사진이 한 덩어리)
- v1.5 지출 히트맵·지역 뱃지, v3 코스 발행(스팟별 선별 사진)의 원천 데이터가 없다

## 선택지

| | 방안 | 장점 | 단점 |
|---|---|---|---|
| A | 현행 유지 (기록 단위 사진) | 입력 마찰 0 | 다지역 기록에서 사진의 지역 정보 없음 |
| B | **사진→스팟 선택 연결** (`record_photos.spot_id` nullable) | 마찰 최소(태그는 선택), 데이터 점진 축적, 코스 발행 대비 | UI 한 단계 추가 |
| C | 지역별 기록 강제 분리 | 귀속 명확 | 한 데이트를 쪼개 입력 — 다스팟 구조·10초 입력 원칙과 정면 충돌 |

## 결정 권고: B를 2단계로

- **1단계 (지금)**: 스키마에 `spot_id` 추가(`0007_record_photos_spot.sql`, nullable·미지정 허용). 기존 데이터·기존 입력 흐름에 영향 없음.
- **2단계 (M1 마무리 때)**: ①기록 작성 시 사진마다 스팟 태그 칩 선택(선택 사항, 기본 미지정) ②기록 상세에서 spot_id 있는 사진은 스팟별 그룹핑, 없는 사진은 "함께한 순간" 섹션 ③오늘 사진 핀 승격 시 해당 스팟으로 자동 연결.
- 원칙: 태그를 강제하지 않는다 — 미지정 사진도 완전한 1급 데이터. 태그는 "더 예쁘게 정리되는" 보상형 선택.
