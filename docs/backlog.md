# 다음에 할 일 (2026-08-02 사용자 메모)

사용자가 직접 적어 준 다음 작업 3건. 순서는 아래 번호 그대로.

## 3. 공유 카드 — 테마 업그레이드 (사용자 커스터마이징)

- 요구: 지금은 고른 스타일대로만 나온다. **사진 위치·크기를 직접 조절**하고 싶다.
- 상태: ✅ **구현됨** (2026-08-02). 전역 '사진 크기' 슬라이더는 없애고 사진별 조절로 바꿨다.
  - 크기: 작게/보통/크게 3단계 — **사진마다** 따로 (메인 한 장 + 서브 구성이 가능해졌다)
  - 보일 자리: 사진 안에서 세로로 어디를 남길지 (얼굴 잘림을 손으로 교정)
  - 기울기: -8~8도, 기본값은 손으로 붙인 듯한 각도
  - 사진 자리: 묶음을 카드 위/가운데/아래 (여러 장 쓰는 스타일에서만)
  - 설정은 사진 URL로 기억해 고른 순서를 바꿔도 따라간다.
- 넣지 않은 것과 그 이유: **끌어다 놓기**. 자유 배치를 열면 못생긴 조합이 나오고, 그건
  "무엇을 골라도 실패하지 않는다"는 v2 원칙(계획 §2)과 스타일 7종을 만든 이유를 무너뜨린다.
  더 필요하면 자리 옵션을 늘리는 쪽으로 (좌/우 정렬 등).

## 4. 데이트 등록 — 스팟별·사진별 코멘트

- 요구: 데이트 장소마다, 또는 사진마다 코멘트를 달 수 있게. 전체 코멘트(지금의 메모)는 유지.
- 현재: 기록에 메모 한 칸(`records.memo`)만 있다. 사진은 스팟에 태그만 걸린다
  (`record_photos.spot_id` — plan-multi-region B안).
- 설계 메모:
  - 스팟별 코멘트는 `spots.note` 컬럼 추가로 간단. 사진별은 `record_photos.caption`.
  - 어느 쪽이 주인지 정해야 한다 — 둘 다 열면 입력 화면이 무거워진다.
    "스팟마다 한 줄"이 데이트 기록의 결에 더 맞고, 사진별은 인스타 캡션에 가깝다.
  - 공유 카드와 연결: 스팟별 코멘트가 있으면 티켓·매거진 카드가 훨씬 풍부해진다.
  - 작성 시트(RecordSheet)가 이미 길다 — 스팟 카드를 접었다 펴는 형태로 넣어야 한다.
- 상태: **입력까지 구현** (2026-08-02). 사용자 결정대로 **스팟별이 주, 사진별 캡션은 하지 않는다**.
  `spots.note`(0016, 120자 · nullable) + 작성 시트 스팟 카드의 접힌 `+ 한마디` 입력까지 됐다.
  남은 것: **기록 상세 표시 · 공유 카드 반영**(`SpotRow.note: string | null`을 그대로 읽으면 된다).

## 5-1. `/install` — 앱 소개 랜딩으로 (2026-08-02 메모)

- 요구: 설치 링크 페이지에 내용을 더 넣어, **'우리의 도화지'가 어떤 앱인지 소개하는 페이지**로.
- 현재: `src/features/install/InstallGuide.tsx` 154줄. 환경(카톡 인앱/사파리/설치됨)을 판별해
  홈 화면 추가 순서만 보여준다 — 기능 소개는 한 줄도 없다.
- 왜 중요한가: 스토어가 없으니 **이 페이지가 사실상 유일한 앱 소개면**이다. 링크를 받은
  사람이 "이게 뭐 하는 앱이지?"를 판단하는 자리이고, 설치까지 갈지 말지가 여기서 갈린다.
- 설계 메모:
  - 순서: ①한 줄 정체성 → ②화면 3개가 뭘 하는지 → ③실제 화면(또는 공유 카드) 보여주기
    → ④설치 순서(지금 있는 것) → ⑤먼저 둘러보기.
  - 소재는 이미 있다: `store-assets/`의 스크린샷 5장·배너, 그리고 공유 카드 렌더 결과.
    새로 그릴 필요 없이 그대로 쓰면 된다.
  - 카피는 명세 §1의 한 줄("지도가 홈, 오늘이 리텐션, 우리가 관계 자산")을 사용자 언어로
    옮긴다. 개발 용어(정복률·리텐션) 금지, 도화지 톤 유지.
  - 이미 설치한 사람이 다시 열 수도 있다 — `step === 'installed'`면 소개를 짧게 접고
    바로 '도화지 열기'가 보여야 한다.
  - 이 페이지는 로그인 전에도 열리므로 Supabase 호출 없이 정적으로만 구성한다.
  - 다크패턴 금지(명세 §5): 설치를 강요하는 문구·닫기 어려운 배너 금지.
- 상태: 착수 가능. 범위만 정하면 됨(스크린샷을 몇 장 넣을지, 스크롤 길이).

## 5. 가계부 — 보기 편하게

- 요구: 가계부를 눌러서 들어가거나 다른 경로로, 지금보다 편하게 볼 수 있게.
- 현재: 우리 탭의 월간 카드 하나(합계·횟수·평균·밸런스)뿐. 개별 지출은 기록 상세를 열어야 보인다.
- 설계 메모:
  - 절대 규칙 1(화면 3개)이 있으므로 **새 탭·새 화면은 금지** — 월간 카드를 탭하면 열리는
    바텀시트가 정답에 가깝다.
  - 시트 안에 있으면 좋을 것: 월 이동, 카테고리별 비중, 지출 목록(날짜·장소·금액·낸 사람),
    항목을 누르면 그 기록 상세로.
  - 명세 §3.3·§5.4 톤 규칙 유지 — 정산 압박·경고색·리더보드 금지.
- 상태: ✅ **구현됨** (2026-08-02). 월간 카드를 누르면 `ExpenseSheet`가 열린다 —
  월 이동·카테고리 막대·낸 사람별 금액과 비율·지출 목록, 항목을 누르면 기록 상세가 겹쳐 뜬다.
  집계는 `expenseSummary.ts` 한 곳에 모아 월간 카드와 시트가 같은 함수를 쓴다
  (예전엔 카드만 별도 쿼리라 숫자가 어긋났다 — 그 쿼리는 지웠다).
