# 공유 카드 v2 계획 — "인스타에 올릴 만한" 수준으로

작성일: 2026-07-31 · 상태: **사용자 검토 대기**

## 1. 지금 무엇이 아쉬운가

현재(v1)는 **테마 6종 = 하나의 고정 레이아웃에 색·폰트·질감만 바꾸는 구조**다.
`shareCard.ts` 788줄 안에서 카드 3종(기록·오늘·종합)이 각각 정해진 순서로만 그려진다.

```
헤더 장식 → 날짜 → 코스 → 사진 그리드 → 메모 → 지역 해시태그 → 워터마크
```

그래서 어떤 테마를 골라도 **뼈대가 같아 "템플릿 티"가 난다.** 색만 다른 여섯 장인 셈이다.
잘 만든 인스타 게시물이 예뻐 보이는 이유는 색이 아니라 **구성(배치)·여백·사진 처리**에 있다.

## 2. 목표

- 자유도는 **낮게**. 사용자가 요소를 끌어다 놓거나 색을 고르지 않는다.
- 대신 **고르는 것마다 완성돼 있게**. 무엇을 골라도 실패하지 않는다.
- 우리만 만들 수 있는 카드가 하나는 있어야 한다 → **지도**.

## 3. 핵심 결정: 프리셋 한 줄 vs 옵션 두 줄

| | 옵션 조합식 (레이아웃 × 테마) | **프리셋 방식 (채택)** |
|---|---|---|
| 고르는 것 | 레이아웃 1번 + 테마 1번 | 완성된 스타일 1번 |
| 경우의 수 | 6×6 = 36가지 (검증 불가) | 8~10가지 (전부 검수됨) |
| 실패 가능성 | 조합에 따라 촌스러움 | 없음 |

→ **화면에는 "스타일" 목록 하나만 둔다.** 내부적으로는 레이아웃·팔레트·장식이
분리된 구조로 만들되, 사용자에게는 묶음으로만 노출한다. 나중에 프리셋을 추가하기도 쉽다.

## 4. 새 레이아웃 (뼈대)

### ① 풀블리드 — 가장 인스타다운 형태
사진이 화면 전체를 채우고, 하단 어두운 그라데이션 위에 흰 글씨.
날짜·장소만 얹는다. 사진이 좋을 때 가장 강하다.

### ② 폴라로이드
사진 1장 + 아래 넓은 여백에 손글씨체 메모. 여백이 주인공이라 사진이 평범해도 산다.

### ③ 필름 스트립
사진 3~4장을 세로로 잇고 양옆에 스프로킷 홀. 하루를 여러 장으로 보여줄 때.

### ④ **지도 카드** ★ 우리만 가능한 것
칠해진 시군구 도형 + 핀 + 코스 선을 카드에 그린다.
"우리가 칠한 곳"이라는 이 앱의 정체성이 그대로 이미지가 된다.
`ConquestMap`의 투영 로직을 캔버스용으로 옮겨 쓴다.

### ⑤ 티켓
절취선이 있는 티켓 모양. 날짜·코스·지역을 표 형태로. 지출은 넣지 않는다(명세 §4).

### ⑥ 매거진
큰 제목 + 작은 사진 + 캡션. 글이 길 때(메모가 좋은 날) 어울린다.

## 5. 부가 요소 — 자동 배치, 위치 조정 없음

레이아웃마다 어울리는 것만 자동으로 붙는다. 사용자가 켜고 끄지 않는다.

- **날짜 스탬프** — 필름 날짜각인 스타일(주황 모노스페이스)
- **위치 핀 + 지역명** — 지도 카드·풀블리드에
- **D+n 뱃지** — 커플 디데이
- **정복률 뱃지** — "대한민국 6.5% 정복"
- **재방문 ×N** — 같은 곳 여러 번 갔을 때
- **마스킹테이프·하트 낙서** — 도화지 톤 레이아웃에만

## 6. 비율 3종

| 용도 | 크기 | 비고 |
|---|---|---|
| 피드 세로 (기본) | 1080×1350 (4:5) | 가장 성과가 좋은 형식 |
| 피드 정사각 | 1080×1080 (1:1) | 여러 장 올릴 때 |
| 스토리 | 1080×1920 (9:16) | 상단 250·하단 340px는 비워 둔다 (UI 겹침) |

지금은 4:5 고정이라 스토리에 올리면 위아래가 비어 보인다. 비율은 버튼 3개로만.

## 7. 품질 디테일 (전 레이아웃 공통)

- **글자 넘침 방지**: 길이에 따라 자동 축소 후 말줄임 (지금은 줄 수만 제한)
- **사진 없는 경우**: 레이아웃마다 대체 구성이 있어야 한다 (지금은 하트 낙서 하나뿐)
- **여백 규칙 통일**: 바깥 여백·요소 간격을 토큰으로 고정
- **폰트 조합 정리**: 제목/본문 짝을 프리셋에 고정 (지금은 테마별로 제각각)

## 8. 실행 순서

| 단계 | 내용 | 비고 |
|---|---|---|
| 1 | **렌더 엔진 분리** — 레이아웃/팔레트/장식을 나누고 비율 가변으로 | 겉보기 변화 없음, 토대 |
| 2 | **지도 카드** | 차별화 1순위, 단독으로도 가치 있음 |
| 3 | **풀블리드 + 폴라로이드** | 체감 개선이 가장 큰 두 장 |
| 4 | **스티커·뱃지 시스템** | 날짜 스탬프·D+·정복률 |
| 5 | **필름/티켓/매거진** | 여력 되면 |
| 6 | **프리셋 큐레이션 + 화면 정리** | 스타일 목록 UI, 비율 버튼 |

각 단계마다 실제 렌더 결과를 캡처해 확인한 뒤 다음으로 넘어간다.

## 9. 위험 요소

- **캔버스 코드가 길어진다** — 788줄이 2배 이상 될 수 있다. 레이아웃별 파일 분리 필요.
- **지도 카드의 투영 로직** — `ConquestMap`은 SVG 기준이라 캔버스로 옮길 때 검증 필요.
- **폰트 로딩** — 프리셋이 늘면 웹폰트도 늘어난다. 지금 4종(1.2MB)에서 더 늘리지 않고
  있는 폰트의 굵기·크기 조합으로 변화를 만든다.
- **미리보기 속도** — 레이아웃이 복잡해지면 그리는 시간이 길어진다. 현재 방식(마운트 시 1회)
  유지하고, 스타일 전환 시에만 다시 그린다.
